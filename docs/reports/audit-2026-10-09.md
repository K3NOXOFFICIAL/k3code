# Full audit and fix pass, 2026-10-09

Scope: every part of k3code — errors, security, missing and badly working features, Claude-Code-style standard
behaviour, self-learning and autonomy, token efficiency, tool-error learning, automatic per-project setup, and a
dynamic test of the installers, updater, service unit and a working setup. Base: Main `ab145ba`. Result: Main
`fdcf783` plus this report.

## How it was verified

- Static audit by area (installer/update/service, autonomy/learning/tokens, security/gateway contract), each claim
  cited by file and line, the worst ones reproduced by calling `permissions.engine.decide` directly.
- A dynamic baseline in fake `HOME`s (installs, re-runs, SIGINT/SIGKILL recovery, offline, no git, fake releases with
  missing or wrong checksums, smoke gate, `service install` without systemd, setup from an answers file, uninstall),
  then the same scenarios again on an integration of every fix. Real install and real systemd units untouched.
- Every change: a test that fails without it, a fresh-context review, at most two review rounds, then the full local
  check (`scripts/ci/check.sh`: shell, vendor, secrets, core, panes, tui) on the merged tree before merging.
- Live checks on the installed build `0.1.0-src.fdcf783`: `k3code update` from the previous git install, `doctor`,
  a headless write-and-run task, the TUI under a pty (`/help`, `/project`, `/exit`), project detection on a uv+pnpm
  project, and the hardened recovery unit started under the real user manager (as a throwaway copy).
