# Changelog

All notable changes are listed here. Until version 1.0, any release may change the config format, the commands or the on-disk state. Versions follow [semantic versioning](https://semver.org/) from 1.0 on.

## Unreleased

### Added

- **`/dashboard` (alias `/display`): one tabbed settings popup in the TUI.** Look (status bar, indicator, compact layout, battery), Details (the global mode and the four sections, each `default` row says what it follows), Input (mouse tracking, what a message typed while busy does, focus view), Context (`/autocompact`: auto, 50-90% or off; a saved `120k` limit shows as its own chip, applied by running the command), Session (model, reasoning effort, permission mode, output style, theme, show thinking: each is applied on `Enter` by its own command, `/model`, `/reasoning`, `/permissions mode`, `/output-style`, `/theme`) and Status (the read-only `/settings` text, scrolled with `↑/↓`, `PgUp/PgDn`, `Home/End`) on one screen. The Session rows and the Status text come from `settings.get`, which answers after the popup is open: the other tabs work at once, and a failed request says why. `/` searches the rows of every tab (label, tab, heading `Model`/`Display`/`Input` as the old panel filed them, id or the value the row had when the popup opened, so changing a row never drops it from the list; `Enter` keeps the filter, `Esc` clears it before it closes, and `Esc` while still typing goes back to where the search began). `←/→` change a row, `↑/↓` move, `PgUp/PgDn`, `Home/End` and `g/G` jump, `Tab` or `1-6` change tab (Alt/Option and Ctrl chords such as Option+arrows do nothing), `Enter` saves (one `config.set` per changed key), `Esc`, `q` or `Ctrl+C` puts everything back; rows paint live while it is open. A click on a tab or a row moves the cursor, a click on a chip picks that option, the wheel walks the rows (and scrolls the Status text). It stays shut, and ignores keys and clicks, while an approval or question is waiting. The Theme row offers `auto`, `light` and `dark` and reads the backend's `default` as `auto` (the old `/settings` panel offered `default`, which `/theme` refuses). Mouse tracking stays `all` by default; `tui/README.md` now explains the trade-off (terminal selection needs Shift, or Option on macOS).
- **`/mouse wheel` and `/mouse buttons` are saved.** The gateway only accepted on/off for `display.mouse_tracking`, so a preset worked for the session and was lost on restart (the TUI also ignored the error). `config.set mouse` now takes `off`, `wheel`, `buttons`, `all` (and `on`/`true`/a bool as before).
- **Dynamic agent creation, and a switch for the number of agents** (`/maxagents`). `/ultracode` now sizes itself from the task instead of using a fixed shape: one planner (no judge call) for a small task, two for a medium one, three otherwise; the plan's top-level steps are grouped into independent units (`(parallel)` marks and shared files decide) and packed into as many workers as the budget pays for, each with its reviewer; the review lenses and the fixer are reserved, so a wide plan can no longer use up the budget before its review and final tests (four subtasks at the default 12 agents used to end at 12/12 inside the review panel and print "0 candidate findings"; the report now says "not run" when the panel did not run). `autonomy.agents.dynamic: false` brings back the fixed shape. The plan-first fan-out of a large task is sized the same way and now has an agent budget (it had none).
- **`/maxagents`** shows the limits, where each came from and what is running, and sets them for the session: `/maxagents 20`, `auto` (the run picks, up to 24), `parallel 6`, `dynamic on|off`, `reset`; `--save` keeps it in `config.yaml`. `/ultracode agents 20` and `/ultracode dynamic off` do the same. New config: `ultracode.max_agents` accepts `auto` and is checked when the config loads (a `0`, a negative or a text value used to fail inside a run), `autonomy.agents.{dynamic, max_parallel, max_nested, max_spawns}`. A session's setting is kept with the session, inherited by `/fork`, `/branch` and `/bg`, and left out of an imported bundle; a project config that sets `ultracode.max_agents`, `ultracode.max_tokens` or `autonomy.agents` is flagged when you trust it.
- **Limits on the model's own `task` calls.** They had none: eight background calls started eight children, and a worker could start five of its own. At most `autonomy.agents.max_parallel` (4) children of a session run at once, a child may have `max_nested` (3) sub-agents, one turn makes at most `max_spawns` (16) calls, and 16 sub-agents run in the whole gateway; past a limit the call fails with a message naming it (nothing is queued, so a worker waiting for its own sub-agent cannot deadlock). Fan-out and `/ultracode` size themselves and are not refused.

### Changed

- **`/settings` opens the dashboard on its Session tab.** It was a separate panel with its own Config and Status tabs; there is one popup now, so everything the panel did (model, effort, permission mode, output style, theme, show thinking, tool details, compact layout, status bar, busy indicator, enter while busy, mouse, search, the Status text) is in `/dashboard`. The panel offered the theme `default`, which `/theme` refuses (it takes `auto`, `light` or `dark`): the Theme row now lists `auto`, `light`, `dark` and reads the backend's `default` as `auto`. `/settings status` and `/settings text` still print the text in the pager. `settings.get` and the `/settings` text now name the theme `/theme` saved (they read `display.theme`, which `/theme` never sets, so a pinned theme showed as `default`) and give a legacy `ask` permission mode as `default`. `/reasoning show` no longer expands a Thinking section pinned to `collapsed`, so Show thinking and a Thinking pin saved together from the popup both stick, and the commands one `Enter` runs all report back (each used to hide the answer and the error of the one before it).
- **Faster agent work.** The two cross-check votes of an `/ultracode` run are asked at the same time (they were one after the other); `task` calls to a read-only agent type (`explorer`, `planner`) in one reply run at the same time (a worker or reviewer still waits its turn); the ultraplan planners honour the session's parallel limit; a fan-out's merge-conflict rework counts against its width (it ran outside it); fan-out can run wider than 3: `autonomy.fanout.max_parallel` was clamped to 3 whatever it said, and is now held to `autonomy.agents.max_parallel` (default 4, at most 8). A setup that wrote 4 (coding) or 6 (research) gets 4. `delegation.status` and the agents view show the width a fan-out really gets.
- **The planning turn asks for `(parallel)` marks** on independent steps, the same as the ultracode planners do, so the plan-first fan-out can tell which steps are independent.
- **bash defaults to 120 s** (was 30 s) before a foreground command is killed, like Claude Code; a test run or a build at 30 s was killed with its work lost and the model had to retry with a timeout. `timeout` still goes up to 600 s and `background: true` is for servers.
- **bash children keep the proxy and the private CA.** A command (curl, pip, npm, git) saw none of `HTTPS_PROXY`, `SSL_CERT_FILE` and the like and failed where a proxy is the only way out. The child environment now includes the CA paths (`SSL_CERT_FILE`, `SSL_CERT_DIR`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE`, `NODE_EXTRA_CA_CERTS`) and the proxy variables, but never a proxy URL that carries a user name or password. A sandboxed command gets the proxy only when it has a network. Provider keys are still never passed.
- **Answers files are checked.** `k3code setup --non-interactive --answers` and `k3code onboard --answers` now reject, before anything is written, a file that is empty or not a mapping, not valid YAML, has a key that no step reads (a typo such as `onboard.provder` used to configure the default provider and exit 0), holds a value of the wrong type, or answers a menu with something that is not on it (`permissions.mode: yoloo` used to be written to `config.yaml` and stop every later start; `usage.primary: foo` was a `KeyError` traceback). A provider entry needs a base URL (or a preset that has one) and an `api_key_env` that is a variable name. Yes/no answers must be `true` or `false` (a quoted `"false"` used to count as true and installed the systemd unit). The error is one line naming the file and the key, with exit code 2; `install/answers.sample.yaml` documents every section, including `onboard:`.
- **Parallel reads.** Consecutive read-only tool calls in one model reply (`read`, `grep`, `glob` and the like, never `bash`) now run at the same time instead of one after another. Any other call waits for the ones before it, a batch that would need an approval prompt runs in order, and results reach the model in the order it asked.
- **Invalid tool-call blocks.** With the `claude-cli` provider, a `<tool_calls>` block that is not valid JSON no longer fails the whole model call and triggers a full retry. Trailing commas, `True`/`False`/`None` and a missing final `]` are repaired; anything else reaches the model as an error result ("Your `<tool_calls>` block was not valid JSON ...") so it can re-send the calls. A block that is opened but never closed is still a provider error.
- **CI runs locally; no GitHub Actions.** The workflows `ci.yml`, `gitleaks.yml`, `installer.yml` and `release.yml` are removed. `scripts/ci/check.sh` runs the same checks on your machine (core, tui, panes, vendor, secrets, plus shellcheck of the shell scripts), with `--quick`, `--changed` and `--only`; `--post` sets the `local-ci` commit status that branch protection on `Main` requires. `scripts/ci/merge-pr.sh` merges a pull request after a full check of its merge with `Main`, `scripts/release/release.sh` builds and publishes a release (the assets of `release.yml` plus the hashed `k3code-<version>-requirements.txt`), and `scripts/dev/install-hooks.sh` installs a pre-commit and a pre-push hook. `scripts/ci/platforms.sh` replaces `installer.yml` as far as Linux can: it installs, updates, rolls back and uninstalls in clean Ubuntu 24.04 and 22.04 (no Go: `--full` checks that the installer fetches its own), Debian 12, Fedora 44 and Alpine 3.20 containers and through `install.ps1` against a WSL stand-in, and reports each step's time. See [`docs/RELEASING.md`](docs/RELEASING.md).
- **A main-tier turn that stalls continues on the strong tier.** After `autonomy.max_tool_errors` (default 8) failed tool calls in a row, or a loop-guard stop, a turn that started on `main` no longer stops and asks: the strong tier continues it with the conversation so far, and the session shows `escalated interactive_turn: main → strong (...)`. Only a stall on strong ends the turn with the list of failed calls and asks for input. Goal continuations and background turns that run on `main` climb the same way; `autonomy.escalate_main: false` keeps the old stop.
- **A goal does not stop on its own (`goal.persist`, default on).** `/goal` now keeps going until the judge says it is done and its `--check` passes, whatever happens on the way: a *blocked* verdict sends the agent to find another way instead of pausing the goal; a judge model that cannot be reached is waited for and asked again (15 s, doubling to 5 minutes) without spending a turn; a check that cannot run is retried the same way; a turn that failed or stopped for input (a question, an approval nobody answered, the loop guard) is retried after the same pause with a prompt that says why; empty replies and unreadable judge replies slow the goal down but never stop it. The continuation prompts no longer tell the model to "say so and stop" when blocked. There is no turn limit (a goal stored with the old default of 300 now reads as unlimited; `--turns N` is still honoured, failed turns count) and no limit on failed checks (`goal.gate_max_retries` defaults to 0, it was 20). What still stops a goal is what you set or do: `--turns`, `gate_max_retries`, a spend budget, the `max_turns` cap, `/stop`, `/goal pause|clear`, `/daemon pause`. `goal.persist: false` brings back the pausing.
- **Money is shown in euros by default.** `/stats`, `k3code stats` and the budget messages ("session EUR budget exceeded: 4.31 > 4.00") show `€` instead of `$`. `currency: USD` brings dollars back, and `eur_per_usd` (default 0.86, an approximation: set today's rate) is the conversion, because providers report costs in dollars and the price table is in dollars; `usage.db` and `k3code stats --json` stay in USD. Spend caps can be given in euros: `reliability.session_eur` and `reliability.day_eur` (converted at `eur_per_usd`; `session_usd` and `day_usd` still work, and when both are set the lower one counts). A bad `currency` or `eur_per_usd` is refused when the config loads.
- **Fewer prompt-cache misses and fewer tokens per request** (from a measured audit of the prompt and tool schemas). The tool list leads every request, so any change in it rewrites the whole cached request:
  - `exit_plan` and `schedule_next`, which come and go, are now advertised last instead of in the middle of the list.
  - `mcp_tool_search` is present whenever an MCP server is configured (it vanished while the server was down at a turn's start and came back after).
  - The MCP tools a session loaded stay advertised through a server restart and are no longer forgotten when one turn starts with the server down (each blip was two full misses and a repeated search).
  - The skills section of the system prompt no longer reorders when a skill is used or the 30-day mark passes (it did, for more than 60 skills).
  - The MCP names in the system prompt are grouped per server, `mcp__Neon__{run_sql, list_projects}` instead of the prefix on every name (about 40% fewer tokens: 1 129 to 677 for 145 tools).
  - `mcp_tool_search` answers with names and arguments (983 to about 80 tokens for six tools), `todo` no longer echoes the list back (87 to 6 tokens per call), the unknown-tool error lists the tools the model was sent (271 to 44 tokens), the base system prompt is 89 tokens shorter, and the note k3code writes into `USER.md` for editors no longer goes to the model.
  - Old `write` and `edit` calls drop their file text from the request together with the old tool results (ten writes of an 8 KB file stayed in every request, 22 000 tokens, until compaction); the file is on disk and the marker says so.
- **Sub-agents that can run `bash` can read and stop background jobs** (`bash_output`, `bash_kill`); `worker` and `reviewer` were told to use them and had neither.
- **A failing provider entry is skipped for a minute.** When another entry can answer, a server error or a timeout puts the failing one on a 60-second cooldown (before, every call tried it first and waited for the failure again). The chain's error says "unavailable" or "rate-limited" according to what happened.
- **The goal check reads only the goal's own turns.** The done-check after a turn sent the whole conversation to the strong tier; it now gets the messages since the goal started (a compaction resets the start), which is what it judges anyway.
- **`mcp_tool_search` answers with names and arguments**, not the full indented schemas: the schemas reach the model through the tool list from the next step on, so the result repeated them.
- **A loaded skill is not cut to 10 000 characters.** The `skill` tool advertised 60 000 but the generic tool-result clip kept the first 6 000 and last 4 000 of a longer one; it now has its own limit like `read`.
- **`/ultraresearch`** cross-checks claims from every sub-topic (the first 60 claims in plan order left the later topics unchecked and labelled "single source"), takes at most `--n 10` sub-topics (`--n 20` made 83 model calls), and `web_fetch` refuses a non-text page (a PDF came back as thousands of replacement characters) and reads a page's own `<meta charset>`.
- **`.k3code/.gitignore`** lists the directories k3code generates (`worktrees/`, `plans/`, `research/`, `reports/`). It contained `*`, which also hid the `rules/`, `skills/` and `config.yaml` the README tells you to commit; a file that holds exactly `*` is replaced, any other content is left alone.
- **Look.** The default theme is hot pink (deep pink, hot pink, violet-red rules, plum fills; darker raspberry on a light terminal). Errors, success, warnings and shell mode keep their own colours. Turns are separated by a full-width rule, the status line is one continuous rule between the conversation and the input, and the agent list has a labelled header (`agents (N) · ← agent view`).
- **Agents.** The agent list under the input is read-only: ↑/↓ always walk your previous inputs and never move into it. ← on an empty prompt opens the agent view, which groups sessions and sub-agents into Needs input, Working and Completed (earlier sessions of the project, dimmed, at the end of Completed) and opens on the current session; ↑/↓ select, → or Enter attaches (on a sub-agent: its live view, Esc goes back), x stops (asks first), n starts a new session, ← or Esc goes back. Finished agents leave the list after a minute.
- **Tool output.** `bash`, `grep` and `glob` results reach the model and the screen as plain text (stdout as it is; stderr, an error note and a non-zero exit code only when there is something to say), not as the Python repr of a dict with every newline and quote escaped. `write`, `edit` and plain errors are one line too (`Wrote /path`, `Edited: 1 replacement`, `Error: File not found: x`).
- **Stored sessions.** At start the daemon deletes stored sessions that never got a message, have no title or per-session setting, are not live or referenced by any loop or automation (paused ones included), and were last touched more than 30 days ago. Every `k3code agents`, `n` and abandoned TUI start used to leave one behind for good.
- **claude-cli streams.** The `claude-cli` provider shows the reply as it is written (`--output-format stream-json`) instead of all at once after several seconds; the `<tool_calls>` block never reaches the screen. It passes `/effort` on as `--effort` (a provider entry's new `effort` field is the default), and its usage records cache reads and writes.
- **claude-cli keeps its process.** The `claude-cli` provider keeps a live `claude -p` process per conversation and sends each step only the new tool results and messages, so the CLI start is paid once and the prompt cache covers the earlier conversation instead of writing it again every step. Any change to the earlier conversation (compaction, a retry, another provider's answer) starts a fresh process with the whole conversation, and a failed step kills its process. New provider entry fields: `persistent` (default true; false keeps one stateless call per step), `max_sessions` (default 5) and `idle_seconds` (default 600).
- **`/help`** lists the gateway's commands by category (it showed only the TUI's own commands).
- **Logging.** `k3code -p` prints only warnings by default, ends the answer with a newline and says why on stderr when a run fails. `K3CODE_LOG_LEVEL=info` brings the log back.
- **Rejected keys.** A provider entry whose key is rejected (401/403) twice in a row now cools down for 5 minutes, doubling per further rejection up to 1 hour (one stray rejection arms nothing, and an entry with no key, such as `claude-cli`, never cools down), so later calls skip it at once instead of posting to it and probing `/models` on every step. The cooldown belongs to the key that was rejected: a replaced key is tried immediately, `k3code doctor` clears it when the key answers, and `k3code onboard` / `k3code setup` clear it after writing a provider. When every entry is rejected the error says authentication failed (and points at `k3code doctor`) instead of "rate-limited until".
- **Usage timings.** The `call` and `tool` rows in `usage.db` now record their wall time in `seconds` (a model call from its first attempt, failovers included, to its answer; a tool from the end of the model message or the previous tool to its result), in the daemon, in `k3code -p` and for side calls such as titles and compaction. They were always 0, so `k3code stats` could not show where time goes.
- **No step limit by default.** `max_turns` (model calls per prompt) defaults to 0, no cap (it was 20). A configured cap that is reached no longer ends the turn silently as if the task were done: the turn ends as needs input with a message saying it stopped after N model calls, an active goal pauses instead of being judged, and `k3code -p` exits 1 with the reason on stderr. Sub-agents are the exception: nobody watches them, so with no global cap they stop after `subagents.max_turns` model calls (default 200; a smaller positive `max_turns` wins) and after `autonomy.max_tool_errors` failed tool calls in a row, and the result they hand the parent says why. Unattended runs (`k3code -p`, automations, background goals) get no separate default cap either (issue #49): a model that keeps making successful tool calls, never repeating one, can spend tokens until the run ends, so set `max_turns` or a `reliability.session_tokens` / `reliability.session_usd` budget for a run nobody watches. Repeated identical calls are still stopped by the loop guard and `autonomy.max_tool_errors` failures in a row end the turn.
- **Goals run until done.** `goal.max_turns` defaults to 0, no turn budget (it was 300), and a failing `--check` pauses the goal after 20 failed checks instead of 3 (new `goal.gate_max_retries`, default 20, settable with `/config`; 0 = no limit, `/goal resume` starts the count again), so a check that can never pass (a typo, a missing tool) cannot burn tokens until someone looks (issue #49). The goal still pauses sooner when it is judged blocked. The status line and notices read `12 turns` / `turn 12` without a budget. `/goal --turns N` still sets one (`--turns 0` = none), and `/goal resume` keeps the budget a goal was stored with, so a goal set before this change keeps its 300.
- **Setup.** Fast setup over an existing config puts the new provider first and keeps the others as fallbacks. `k3code doctor` reports a provider without a key as a warning while another provider can still answer.
- **`/model`, `/effort` and bare `/ultracode`.** `/model` and `/effort` now run through the same code as `/tune`; their arguments and replies are unchanged. A bare `/ultracode` used to print a usage line and now flips the ultracode mode. `model.options` reports the model key of the session asked about, not only `default_model`.

### Added

- **Spend is priced per model.** The USD budgets (`reliability.session_usd`, `day_usd`) charged every call at one blended rate, so a day on Opus and a day on Haiku cost the same on paper. A call is now priced by the model that answered (the router tags it, so a failover to another model is priced as that model): the provider's own figure first, then `models.<id>.price: {input, output}` (USD per million tokens) from your config, then a built-in table of the Claude and GPT families, with Claude's cache reads at 10% and writes at 125% of the input price. A model with no price keeps the blended rate.
- **Sub-agents spend the parent's budget as they go.** A child had its own fresh budgets and charged the parent only when it finished, so a fan-out of N children could spend N times the session cap and a runaway child was not stopped until it returned. Its governor now reports to the parent's with every call, and the parent's limits stop the child.
- **A test that the TUI and the core agree on method names** (`tests/test_tui_rpc_drift.py`). It reads every RPC method the TUI sources call and fails when the core has no handler for one, unless it is listed with a reason (the skills, plugins and journey overlays and the batch clarify cannot be opened in this TUI). `spawn_tree.save`, called after every turn with sub-agents, is acknowledged instead of answered with "unknown method".
- **Prompt cache for Claude behind a relay.** An `openai` provider serving a Claude model sent no cache markers unless `prompt_cache: on` was set, so every request paid for the whole conversation again. `prompt_cache: auto` now sends them for Claude model ids and, if the relay answers 400 to a request with them and accepts it without, drops them for the rest of the run (and logs it). `on` always sends them, `off` never.
- **`/autocompact`.** Sets when a conversation compacts itself, like Claude Code's auto-compact: `auto` (70% of the model's window, the default), a token limit (`120k`), a share of the window (`60%`) or `off`; `--session` changes this session only. `/autocompact` alone shows the limit and how far the session is from it. A limit is saved as `context.compact_at_tokens` / `compact_at_ratio` (and `context.autocompact: false` for off) in the user config; a project `context:` section that replaces it is named in the reply. With `off` a request the provider rejects as too long is no longer compacted behind your back: it fails and the TUI says to run `/compact`. The `context.*` keys are checked when the config loads (`compact_at_ratio: high` used to raise inside every turn).
- **`/compact <focus>`.** Tells the summary what to keep. `/compact` now uses `context.keep_messages` and `context.compact_input_chars` like automatic compaction (it used a fixed 6 messages), reports the tokens saved, and counts toward `Compressions` in `/usage`.
- **Context and cache numbers in the TUI.** The core never sent `context_used`, `context_max` and `context_percent`, so the status bar's context meter and `/usage` showed nothing. `session.usage`, `message.complete` and the `session.usage` request now carry them, plus where automatic compaction starts, the compaction count, and the prompt-cache hit rate. `/usage` shows the cache hit rate and the compaction point, and no longer wipes the status bar's context meter. The TUI shows "compacting" while an automatic compaction runs.
- **`cache_ttl: 1h` on a provider.** Marks prompt-cache breakpoints with a one-hour lifetime. A `/loop` or cron job that comes back after 5 minutes or more found its 5-minute cache entry expired on every tick. Off by default (a one-hour entry costs more to write).
- **Decision model for context (optional, off by default).** With `context.decision_model.enabled: true`, a small, cheap model reads the old tool results a long turn is about to drop from the request and decides per result: keep it whole, or drop it and keep a short note of the facts that still matter (paths, line numbers, values, errors). The main model gets fewer input tokens without losing what it is working with. It runs only where old results are dropped anyway (in batches), so it adds no prompt-cache misses, and any failure falls back to plain dropping. It uses the cheap tier (`task_tiers.context_select` picks another), or a named model: `model: <id>` and optionally `provider: <provider block name>`. `at_ratio` (default 0.5) sets the share of the context window at which it starts; an invalid setting turns it off with a warning.
- **Self-verified gotchas apply on their own.** A tool failure that came back twice in a project within 14 days, and whose retry worked (for example `python3 x.py` after `python: not found`), is noted for the in-turn reminders on its own (in `gotchas.auto.md` next to the project's `gotchas.md`) and proposed as a project-gotcha card at the same time; the session gets a one-line notification saying it was noted and can be promoted. A noted line is tool output plus the model's retry, so it never goes into the system prompt: only an accepted card puts it there. It is learned once per signature. A failure without a working retry still waits for the third sighting and the card. Denials, invalid arguments and hints the scrubber redacted something in are never learned this way. Set `learning.auto_gotchas: false` to keep the card for every gotcha.
- **Auto-continue (opt-in).** With `autonomy.auto_continue: true` an ordinary prompt typed in a session runs like a `/goal` of its own: after each turn the cheap judge reads the reply, and while it says continue a continuation prompt starts the next turn, so a model that stops early ("next I would…") carries on until the judge calls it done or blocked. A question or chat counts as done once it is answered, so it costs one judge call and no extra turn. The goal snapshot carries `implicit: true` for it, and the goal bar labels it `↻ auto goal`. It ends cleared, never paused: done, blocked, interrupted, needs input, halted or failed, there is no "Goal paused… /goal resume" notice, the daemon never restarts it, and the next prompt or a `/goal` replaces it. A `/goal` that is active or paused is left alone. Background, cron, loop and automation turns, sub-agents and `k3code -p` never auto-continue. Off by default.
- **A known fix is shown when the failure comes back.** When a tool call fails in a way the project already has a lesson for (a known pitfall, or a retry that worked within the last 14 days), the model gets a one-line `[learned]` reminder right after the step's tool results that quotes the recorded failure and the retry that worked as data (« », not an instruction), once per failure per turn and next to the loop guard's own reminder. The system prompt is not changed mid-turn. A pitfall accepted from a card in two or more projects (never a line only noted automatically) is also kept in `$K3CODE_HOME/gotchas.md` and shown in the system prompt as "Known pitfalls on this machine", and its reminder reaches every project.
- **`/tune`: model, effort and ultracode in one popup.** In the TUI `/tune` opens one screen: `↑`/`↓` pick the model, `←`/`→` the reasoning effort (`default`, `low`, `medium`, `high`, `xhigh`, `max`), `Tab` the ultracode mode, `Enter` applies it and makes the highlighted model the default for new sessions (`s` leaves the default alone), `s` applies it to this session only, `Esc` cancels. A bare `/model` and a bare `/effort` open the same popup. Typed, `/tune [model <key>|<key>] [effort <level>|<level>] [ultracode [on|off]] [--global]` takes the words in any order, checks all of them first and applies all or nothing; an unknown word is an error and changes nothing. The old picker's spellings still parse (`--reasoning <level>`, `minimal`/`ultra`/`none` after `effort`, `--provider`, `--tui-session`). `/model <key>`, `/model chain` and `/effort <level>` keep working and say what they said, and `/model <key>` takes `--reasoning` and `--global` too. New RPCs `tune.get` and `tune.set` serve the popup (`tune.set` is refused in a read-only attach, as `config.set` is; a provider that does not define a key contributes its default model to a row's `providers` and `resolved`) (one row per model key with the model ids it resolves to, whether the model takes an effort level, and an optional description from the new `descriptions: {key: text}` on a provider). The popup fits 80x24, drops the descriptions below 70 columns, and stays closed while an approval, question, password or confirm prompt is open. `/help` lists `tune` under "Model and settings".
- **The default model is saved.** `/tune ... --global`, `/model <key> --global` and `Enter` in the popup write `default_model` into the user `config.yaml`; before, a model switch without a session changed the default in memory only and a restart lost it. The write follows `/model chain`: the key must exist, the result is validated, a timestamped backup is made, then the file is written. A failed write is reported and applies nothing else from that request. Only the user config is written, never the project's. The rewrite does not keep YAML comments; the backup does.
- **Ultracode mode.** `/ultracode` with no argument flips a per-session mode, `/ultracode on`, `/ultracode off` and `Tab` in the popup set it, `/ultracode status` reports it, and the status line shows an `ultracode` chip while it is on. With the mode on, a prompt you type runs the ultracode pipeline when the plan-first scope classifier rates it at least `ultracode.min_scope` (default `small`, so everything except `trivial`); `trivial` prompts and a classifier failure run as a normal turn. The mode skips slash commands, text the TUI generated, a prompt with an approved plan (`/go` after `/ultraplan`) and background sessions. It is kept with the session, restored on resume and inherited by `/fork`, `/branch` and background sessions; `session.info` carries `ultra_mode`. `/ultracode <task>` is still a one-shot run and does not change the mode.
- **Wake words.** Typing `ultracode`, `ultraplan` or `ultraresearch` in a prompt runs that mode once on Enter, with the word removed from the task (your own text stays in the transcript). A word counts only when it stands alone: not in a slash command, a path, a flag, an `@mention` or a `#tag`, not quoted or in code, and not when the prompt names two different wake words. A prompt that is only the word gets the command's usage line, and the composer paints a word that counts in the accent colour while you type. `ultra.progress` reports the phases `wake word` and `ultracode is on` first. Typed `ultracode on|off|status` (also "turn off ultracode") sets or shows the mode instead of running. `UserPromptSubmit` hooks run before a wake word or the mode routes a prompt, so a blocked prompt reaches no model, and a hook's context goes to the run. Detection is linear in the prompt length. Quote or backtick the word to say it without running anything, or set `wake_words.enabled: false` (or `wake_words.ultraplan: false` and so on per word). Wake words do not apply to `k3code -p` or the line REPL. Security: only text you typed is checked (a sent prompt, a queued or steering prompt when it runs, `/bg <prompt>`), so tool output, goal prompts, loop, cron and automation ticks, sub-agents and anything the TUI generated (`/skill` expansions, the `/go` send, an accepted proposal) cannot start a multi-agent run. `prompt.submit` and `session.steer` take an `automated` flag for that; the TUI sets it on the prompts it generates.
- **Project recipes.** k3code detects every stack of a project, monorepos included (Python, Node/Deno, Go, Rust, Nix, Docker, Home Assistant, Java, Ruby, PHP, Terraform, Ansible, .NET, Make/just, CI), with the test, lint, format and build commands read from its files (nothing is run). The result is kept in `$K3CODE_HOME/projects/<project>/project.json`, not in the repository, and a changed marker file triggers a re-scan that proposes only what is new. Each stack offers opt-in proposal cards: matching skills to pin, an MCP server (a docs server; for Home Assistant its MCP endpoint, with the token named by `HASS_TOKEN`), a formatter hook after edits, exact-command allow rules for its test and lint commands, and its commands to confirm. Accepted rules, MCP servers and hooks apply to that project only. The system prompt gets a short "Project facts" section, the skills index lists the project's matching skills first, `k3code setup`/`onboard` offers the recipes (`project_recipes: accept_all|none|ask` in an answers file) and `/project` shows the stacks and pending proposals (`/project rescan` re-scans).
- **Background bash.** `bash` takes `background: true`: the command goes through the same permission decision and sandbox as any `bash` call and returns a `job_id` at once. `bash_output` returns what the job printed since the last read and whether it still runs; `bash_kill` stops its process group. Both are allowed without a prompt and reach only jobs of the calling session; a session's jobs are killed when the gateway closes it or shuts down, a sub-agent's when it finishes, and a `k3code -p` run's or REPL's when it exits. The `bash` schema documents its timeout (default 120 s, max 600 s), and a timeout says how to go on.
- **Learning from tool errors.** Tool arguments are checked against the tool's schema before the call (and before any approval prompt): the model is told what is missing or wrong and what the tool expects, instead of `Tool execution failed: 'path'`. A failure that recurs in a project (3 times in 14 days) is proposed as a project gotcha; accepted ones are kept in `$K3CODE_HOME/projects/<id>/gotchas.md` (never in the repository) and shown to the model as known pitfalls. The reason typed with a denial is kept (scrubbed), and two similar reasons for the same command become a preference proposal.
- **Loop guard on results.** The same failure three calls in a row (whatever the arguments) or two calls alternating over six calls gets one specific reminder; a turn on the top tier it may reach stops after `autonomy.max_tool_errors` (default 8) failed calls in a row and lists them (a main-tier turn first continues on strong, see above).

- **Agent view.** `←` on an empty input, `/agents` or `k3code agents` (on the daemon) opens a full-screen list of every session and sub-agent by state, plus earlier sessions of the current project; `session.list` rows now carry the session's `cwd`, and a `cwd` param filters the list to that project on the gateway.
- **`sandbox.home_readonly`** (user config only): `$HOME` entries that stay visible, read-only, inside the bash sandbox, for example `[".myapp"]`. The sandbox hid all of `$HOME`, so a model that checks a marker file in the home folder could never see it and repeated its first-run question in every `auto`/`yolo` session.

### Fixed
- **Keeping a request inside the window** (twelfth pass: elision, the token estimate, the read budget). *A big result no longer bricks a small window:* one `read` of ~70 KB in an 8k or 16k window (or 60 000 Chinese characters in 32k or 64k) made a 16 000-token request, the turn failed and so did every later prompt, and `/compact` found nothing to fold. A tool result is now sent at most 20% of the window, cut by its own chars per token (at least 4 000 characters), and a request still past 85% of the window after the elision has its largest results cut down to 5% each (`clip:<id>` in the session's elision state, so the prefix stays stable). *`max_tokens` follows the room:* a 6 700-token prompt asked for 2 000 tokens of reply in an 8k window and the provider rejected the sum; the reply limit is now lowered to what the window leaves (2% and a few tokens kept free, never below 256). *The estimate follows the text:* `chars // 4` was 0.35-0.45 of the real count for base64, hex, UUIDs and ANSI colours (a 128k window overflowed at 91% with the estimate at 43%, so elision and compaction never started), 0.6-0.7 for logs, diffs and minified JSON, and 8 to 31 times too large for runs of newlines and spaces; it now weighs lower-case text, capitals and digits, punctuation and blanks, the switches between them and non-ASCII characters, fitted to cl100k counts (within +-30% for source, docs, JSON, logs and hashes; short text is still `chars // 4`, and a long result is judged on three windows of its text, so it costs the same at any size). *Elision:* the results of a step of more than six parallel calls reached the model with the oldest already elided; every result the model has not seen stays whole up to 40% of the window. The file text of a `write`, `edit` or `bash` heredoc that failed is no longer replaced by "they are in the file now". A background job's `bash_output` and an `advisor` answer are kept like a sub-agent's report, a loaded skill whatever its size, and the marker of a result that a repeat does not give back (`bash_output`, `advisor`, `bash`, `task`) no longer says to re-run it. *The same `[learned]` note* is no longer added to the conversation every turn.
- **A usage.db write error no longer fails a turn.** Recording a usage event (a model call, tool, failover or approval) is best effort: a locked or full database, a read-only disk or a closed connection used to raise out of the router callback, abort the failover to the next provider and fail the turn. The error is now logged at warning level (at most once a minute) and the event is dropped. Nothing changes while writes succeed (issue #148).

- **Audit of cache hits, compression, context length, tokens and failed tool calls** (a measured audit, each finding re-run and tried to be refuted before it was fixed):
  - *Provider errors.* A 429 "Request too large … Limit 30000, Requested 45678" (OpenAI, Groq) is a prompt that no wait admits: it compacts and retries instead of parking the turn for hours. Overflow wordings of DashScope/Qwen, TGI, Together, SGLang, LiteLLM and `claude -p` are recognised (the user was told the model was unknown). Bedrock's "Too many tokens, please wait before trying again" is a throttle, not an overflow, at every status. A Gemini per-minute 429 is a rate limit, not a billing wall that parks the entry for an hour (a daily or zero allowance still is). OpenRouter's `error.metadata.raw` (the upstream's own text) and a plain-text or HTML error body are kept in the message instead of "HTTP 400", so the overflow or the WAF page is classified. vLLM's "max_tokens is too large … context length … input tokens" is an overflow when the input is the big part. `claude -p`'s output-limit error is not retried as a server error.
  - *Output cap.* The reply cap is never above a quarter of the model's window (an 8k-window model could not answer "hi"; its `max_tokens` was 8192). A reply that spends the whole cap on reasoning and writes nothing is retried once with a larger cap and then says so, where it used to get three "continue" requests about an answer that did not exist. A `model_context_window_exceeded` stop is an overflow (compact and go on), not a finished answer. OpenAI's o-series and gpt-5 get `max_completion_tokens`.
  - *Elision.* Tool results from 300 characters up (was 2 000) are elided once old, so a turn of many small reads or commands no longer overflows after a few hundred calls; the newest results stay whole only up to 15% of the window (a few huge results made most of the request "recent" and rewrote the cache on every step). `-p` and the REPL now elide and stop on repeated tool failures like the gateway does.
  - *Compaction.* An overflow in the middle of a turn keeps the tool calls already made and continues from them (it threw them away and ran the prompt again, repeating pushes and migrations). The summary model reads the end of tool results and whole later user messages (11-18% of the folded text before). A first prompt longer than 12 000 characters keeps its end as well as its start. The todo list survives a compaction that folded the call that wrote it. A prompt bigger than the window is clipped in the stored history, so `/compress` and the next prompt work. The compaction trigger counts a tool call's arguments once. `models.<id>.context_window` accepts `200k`/`1M` and ignores unusable values instead of failing every prompt.
  - *Cache prefix.* The learned notes the background review writes no longer change a running session's system prompt (every note rewrote the whole conversation in the provider's cache); they are read again after a compaction or `/clear`. `exit_plan` is listed in every mode of a session, so entering and leaving plan mode does not rewrite the tool list. The `claude-cli` process pool defaults to 5 (a parent and its four children).
  - *Tool errors.* A reply is one step for the tool-error stop: eight parallel failing reads were a stall (and a move to the strong tier, with a cold cache) before the model had read one error. A `bash` command that exits 2 or more, or non-zero with something on stderr, counts as a failed call (exit 1 with no stderr, the grep/diff/test convention, does not). `bash` runs under bash, not dash. A failure in the sandbox says what the sandbox did (read-only `.git`, no network, private `/tmp`), and a background child it killed is reported. `edit` says "No change needed" only for an edit it applied itself, and keeps a tab-indented file's tabs when the model wrote spaces. `grep` retries once with `-U` or `--pcre2` when ripgrep asks for it; `glob` prints paths relative to the session directory (they work in `read`). Arguments a built-in tool does not take are named in its result. Tool-call JSON with a raw newline in a string is accepted, and a broken one says where it breaks. A progress bar's redraw frames are reduced to the last one.
  - *Second pass (the findings the first pass could not confirm, checked one by one).* The session's `/effort` no longer reaches one-shot side calls (a title, a verdict or a summary at `max` spent its small reply cap on reasoning). An attempt that died after the provider counted its prompt (a stream cut mid-answer, or stopped with `/stop`) is charged to the budgets; Anthropic input counts finalized in `message_delta` are read; OpenRouter's reported `usage.cost` is used. The day's token and money caps start from what the usage log already holds for today, so a daemon restart or a new `-p` process does not hand them out again. Background sub-agents that finished are listed once at the next turn, and those a cron or automation run left behind are stopped with the run. A failed recovery turn of a goal no longer leaves its unanswered prompt in the history (17 an hour while a provider was down). The session review does not run on loop ticks, cron runs or automations. A misspelled key under `context:` (`compact_at_token`) is warned about at load. `/autocompact` says when its limit is below what every request carries before any conversation. The two `/ultracode` cross-check votes get only the diff of the files their findings name. The plan critique's task text is capped. `model.save_key` answers with where keys come from (it answered "missing provider" to the picker). `gpt-4.1-nano` has its own price.
  - *Third pass (what the first two left as it was, reconsidered).* The parallel workers of a fan-out cache their shared system prompt once: a sub-agent's system prompt is two messages (what agents of its type share, then its own task), which the native Anthropic API caches as two blocks, where one block made every sibling a different cache entry (other providers still get one message). A 1-hour prompt cache (`cache_ttl: 1h`) is priced at 2x for its writes, not 1.25x. The goal reviewer's summary of a growing conversation is extended with what is new instead of redone from the start at every "done". An `edit` whose `old_string` was copied with `read`'s line numbers is told so. The background learning calls and the next-step proposals have their own task kinds (`learning`, `proposal`) in the usage rows instead of counting as `classification`; a `task_tiers` entry for `classification` still applies to them until they get one of their own. A call a server sent no usage for is estimated for the budget guard only (the log and the status bar still show nothing rather than a guess).
  - *Spend.* `ultracode.max_tokens` is a budget of the session's governor, so every child stops right after the call that crosses it (one worker spent 21 times the cap). Side calls (compaction, classifier, judge, advisor) count against the session and day budgets. The price table follows the current models (Opus 5.5 $4/$20, Sonnet 5 $2/$10, Haiku 5 $0.10/$0.50, Fable and Mythos $10/$50; the older Opus keep $15/$75) and OpenAI's cached input is discounted. DeepSeek's and Moonshot's cache hits are read (the status bar showed 0%). A persistent goal that stays blocked waits longer each turn (180 turns an hour before). A long goal is quoted by its start in continuation prompts, and in full again when no message holds it any more. The planning turn sends the older conversation as prompts and answers only. A failed worktree sub-agent says which branch holds its work. The scope classifier reads at most 4 000 characters of a pasted prompt.
  - *Fifth pass (a regression review of the four audit commits, then a second sweep; each finding re-run before it was fixed).* A second `/compact` of a session that began with a long first prompt left the first summary out of what the summarizer read (the first prompt filled the head of its input); the first prompt is now shown to it in brief, as it is kept whole in the result anyway. A *read-pointer* ("unchanged since the read …") whose earlier result a compaction folded away is reworded instead of claiming the content is "above". The newest step's results stay whole when a lesson, a loop-guard note or a steering message follows them. Results the session had elided stay elided when the next request has a larger window. An attempt that died after counting its prompt is charged even when the retry goes to a provider that counts nothing up front. The stop message reports the real number of failed calls. `/stop` during the summary call of an overflow retry no longer drops the turn's prompt and tool work; a background sub-agent's note is marked as read only after the model answered the prompt that carried it; moving a session to another project shows that project's learned notes; a side call before a resumed session's first turn is charged; an overflow continuation counts the model calls already made against `max_turns`. - **Heredocs in the permission checks.** The shell expands the body of a heredoc with an unquoted delimiter (`cat <<EOF`), so a `$(...)` or backtick in it runs. Such a command no longer matches the read-only allowlist (it asks), the payloads go through the hardline checks like any other substitution, and the script a heredoc feeds to a shell (`bash <<'EOF'`, `cat <<'EOF' | sh`) is checked like `bash -c`. A heredoc an interpreter runs as its program is never covered by an allow rule, and one fed to `ssh host` with no remote command is a script for that host, checked command by command like `ssh host '...'`. The delimiter and the end of the body are found the way bash finds them (the whole word with its quotes removed, a quote anywhere in it makes the body data, a delimiter line that matches exactly, `\<newline>` joined in an unquoted body, a `<<` in `((...))` is a shift, also when the `))` is on a later line); a `<<` the parser cannot place needs a person and the lines after it are checked as commands, so the hardline sees them in `yolo` too: one inside a `${...}`, `$[...]`, subscript or `a=(...)` that is still open, however far back on the command it opened, after an `a=(...)` that bash rejects, after a `$(...)` that ends inside such a bracket, a word bash versions read differently, a heredoc opened in a `$(...)` that ends on its line. A quoted delimiter still keeps the body as data.

- **Agent view time (#40).** The agent view and the inline agent strip counted a live session's "working" time from the day the stored session was created, so a resumed session showed `working 1370m` minutes after launch. `session.active_list` rows now carry `turn_started_at` (the wall-clock start of the running turn, `null` between turns) and the TUI times the row from it; `started_at` stays the creation date, which the session switcher still shows as the session's age. Rows between turns show no time.
- **`k3code -p "/cmd"` runs slash commands (#27).** A `-p` prompt whose first word is a registered slash command used to go to the model ("isn't a command I recognize"). `/project`, `/skills`, `/stats` and `/help` now run without a provider and print their output (`--json` gives the same fields); the commands that need a live session (`/clear`, `/model`, `/doctor`, ...) fail with one stderr line and exit 1, as does a command that raises. A prompt that only starts with a path, such as `/etc/hosts explain this`, still goes to the model.
- **`k3code doctor` and a never-scanned project (#28).** The `project` check read `none` (the trust state of a project without a config) until a TUI session had scanned the project. It now runs the read-only stack scan itself and names the stacks it finds, and `/project` before any scan says "Not scanned yet" with how to scan instead of "No stacks detected".
- **`/help` overlay (#29).** A command name wider than the name column ran into its description (`/details [hidden|collapsed|expanded|cycle]set global ...`, `Shift+Enter / Alt+Enterinsert newline`). Each row is now padded to its own name plus two spaces (at least 20 cells).
- **Context window of unknown models (#30).** A model id with no `models.<id>.context_window` and no known family, such as a gateway alias like `auto/coding-manual`, got a 32k window, so compaction started at about 22k tokens. The fallback is now 128k (a provider's context-overflow error already makes the gateway compact and retry once), and the `sonnet`, `opus` and `haiku` aliases get 200k. `k3code doctor` warns about each chain model whose window is a guess and shows the `models.<id>.context_window` line to set.
- **Install lock and recycled pids (#31).** `install.sh` and `k3code update` took over a stale install lock only when its pid was dead; if an unrelated process had reused the pid, installs stopped until the user ran `rm -r <data>/.install.lock`. Both now write the owner's process start time next to the pid (before it, so a lock with a pid always has one) and take the lock over when the pid is alive with a different start time. A lock without a start time (an older installer) keeps the pid-only rule.
- **Installer and CLI polish (#37).** A killed install left its TUI build directory (`$TMPDIR/k3code-tui.*`) behind; the lock now records it and the next install removes it (only a `k3code-tui.*` directory directly under the temp dir, also when `TMPDIR` ends in a slash as on macOS). `install.sh --from-source` without git named every build `0.1.0-src`, so a second checkout looked already installed; it now appends a checksum of the files the install reads (`VERSION`, `core/`, `tui/`, `panes/`), and stops with a clear message when neither `sha256sum` nor `shasum` exists. `k3code service install --dry-run` prints `k3code-recover.service` as well as `k3code.service`. `k3code --version` names the running install (`k3code, version 0.1.0-src.<sha>`) so two installs can be told apart.
- **Test runs that never finished (#42).** NetWatch's two background loops kept running when a cancel was lost inside httpcore/anyio (the probe came back with a proxy error instead of `CancelledError`), so the event-loop teardown of a test waited for them for ever and `scripts/ci/check.sh` hung. The loops now check at the top of every round whether their task was cancelled and end. The pytest step of `check.sh` also has a time limit (45 min, `K3CODE_CI_PYTEST_TIMEOUT` seconds to change it), and a test stuck for 5 min prints every thread's stack.
- **Headless slash commands and the project scan (#43).** `k3code -p "/project bogus"`, a command that only prints its usage line, now exits 1 like a command that raises; `-p "/help"` and `-p "/skills"` run without opening the home databases (they created `sessions.db`, `usage.db` and others in `$K3CODE_HOME`). A workspace glob such as `packages/**` reads at most 2000 directories per scan, shared by all globs, and goes at most 6 levels deep (and, like pnpm, no longer matches hidden directories with `*`); a very large monorepo made `k3code doctor` slow.
- **Context window in `k3code setup` (#43).** After the model tiers, setup asks for the context window of each chosen model id k3code has no figure for (a gateway alias, a small local model) and writes it as `models.<id>.context_window`; blank keeps the 128k assumption. `32000`, `32_000` and `32k` are accepted. An answers file gives them as `tiers.context_windows: {<model id>: <tokens>}`. Ids that already have a window in the config are not asked again, and a re-run of the `tiers` step keeps the other `models` entries.
- **Permission engine hardening** (it only tightens: every decision that was a deny stays a deny and nothing that asked now allows, checked on about 5 500 commands in five modes). `<>` and `>|` redirects count as writes; shell keywords and braces, more wrappers, `find -exec`, `ssh host cmd`, scripts fed to a shell, assigned command names and ANSI-C quoting no longer hide a hardline or deny-rule match. `rm` targets resolve against the working directory and `cd` targets, and glob or `..` targets under protected roots are denied; unresolved expansions, nesting past six levels and unreadable scripts need a person. New hardline denies: block-device writes, recursive `chmod`/`chown` on `/`, `find / -delete`, fork bombs; a force push without a branch asks. `write`/`edit` on git hooks and config, `.husky`, `.envrc`, shell startup files, keys and `.k3code/config*` ask in every mode. `grep` with an include glob never searches dotenv files or key directories. A malformed user hardline regex is logged and matched literally. "Always" approvals no longer persist a command that carries a secret.
- **Automation, sandbox, trust and redaction.** One automation engine per home (a lock), default cooldowns for self-triggering watchers, a busy webhook port no longer stops the daemon, failed loop ticks do not use the budget, cron handles Sunday, day-of-month and an interval floor, sleeps survive a suspend, cron automations respect offline and `/daemon pause`, a goal `--check` that cannot run pauses at once, `/update` keeps its environment and downloads only this platform's binary (the token goes only to the GitHub API), and a failed service install says so. A planted `.git` file or symlink can no longer bind `$HOME` or another path into the sandbox, and `bwrap` runs with `--cap-drop ALL`. The trust summary shows the values of security-relevant keys, and what is trusted is the content that was shown. More credential shapes and dictionary keys are redacted, and a quadratic slowdown in the redactor is gone.
- **Learning, goals and sub-agents.** Learning files (`USER.md`, gotchas, preferences, proposals, experiments, the decision log) are written atomically and survive a lone surrogate; proposal ids are unique across processes; a corrupt `experiments.json` is kept as `.bad`. Maintenance runs one pass at a time with a back-off, permission mining and the optimizer's replay run off the event loop. A sub-agent cancelled before its first step is finished instead of left queued, side calls are priced with the model that answered them, and a custom agent with a YAML `tools` list keeps its limit. A reviewer veto on the last budgeted goal turn is not reported as achieved, a damaged `halt.json` fails closed, stale-skill cards archive the skill that was judged, and `blockers.db` is indexed and pruned.
- **Commands, setup, config and gateway.** A project's trusted config no longer leaks into the shared server config; `/permissions rm` keeps trust; `setup --step` merges instead of deleting; yes/no answers in an answers file are parsed; an apostrophe no longer breaks a quoted flag; `/rename` sticks; `/config set` validates; config writes are atomic and keep their mode; a rollback restores the commented backup; `/debug dump` redacts MCP secrets; `-p ""` and a failing `$EDITOR` give messages; bundle sessions are type-checked. The gateway survives a lone surrogate, a malformed JSON-RPC frame can no longer end its read loop, and an invalid `permission_mode` is refused.
- **MCP, research, skills and memory.** HTTP MCP servers connect, `tools/list` is paginated, clashing server names are refused, resource and structured results come through, and a dead server is revived within the turn. Research no longer picks the web search tools of other services, null claims and a failing read no longer end a run, and login or paywall classification ignores scripts. Skill frontmatter, memory (no double import, lossy append), output styles, artifact ids and the `usage.db` turn index got fixes. `.k3code/.gitignore` lists the generated directories instead of `*`. `tests/test_tui_rpc_drift.py` checks that every method the TUI calls has a handler or a documented reason.
- **TUI composer and turn state.** `!cmd` during a turn no longer clears the busy state, so Ctrl+C and the queue drain still see the running turn; a prompt sent after Ctrl+C keeps the interrupted flag until its own turn starts and the old turn's closing events are not appended twice; Ctrl+K sends only from an empty composer; a session switch or reconnect keeps paste tokens with the draft; Down in a recalled multi-line entry moves within it; text-presentation symbols are one cell wide; paste labels never cut an astral character; Ctrl+V normalises CRLF.
- **Panes, scripts and shared helpers.** The `k3keys` key-binding hook and keymap, the release and local-CI scripts (shellcheck-clean, signal-safe, refusing a rule file that would make the personal-data scan fail open), and the shared TUI helpers (ANSI, colour, fuzzy matching, JSON-RPC channel, reconnect back-off, OSC) got a round of fixes with tests.
- **A failed review no longer starves the other subtasks of a dynamic run.** The agent budget reserves the review tail, and the rework and re-review of one rejected subtask used the agents its siblings' reviewers needed: at the default 12 nothing merged, the review panel never ran, and the report said the final tests passed on an unchanged tree. Each subtask's worker and first reviewer are now paid for when the fan-out starts (what a subtask does not use goes back to the pool), so a rejection costs only its own retry; one that cannot get its retry is reported as unresolved with the branch that keeps its work (`## PARTIAL` in the report). The report says "not run: nothing was merged" instead of running tests on an unchanged tree, names how many subtasks the tests covered when some did not merge, and carries `Sizing:` and `Timing:` lines (`ultra.progress` gets `elapsed_s`). The final-test skip needs the run to be in the repository root the fan-out tested.
- **Sizing is more careful.** One planner (no judge) only for a task the classifier rated trivial or small, low risk, needing no plan; a medium task, one the safety floor flagged, one rated with `/scope` and one the classifier could not rate keep three, and a failed only planner is replaced by the next angle. Scope no longer caps the number of workers (a trivial or small task is one worker; the budget and the limit of eight decide the rest). Steps that name the same file stay together even when the planner marked both `(parallel)`; planners and the planning turn are asked to end each step with `[files: path/a.py, path/b/]`, which replaces the guess; "read/write" and "node.js" are not paths; numbered items win over bullets at the same indent, and fenced blocks are not steps. A plan whose steps come down to one unit is no longer fanned out by falling back to the classifier's suggestions.
- **Safer parallel `task` calls.** A list or object where an `agent_type` belongs no longer raises out of the turn (the call gets its normal invalid-arguments answer); a run of read-only calls longer than the session's parallel limit is cut into chunks instead of having the extras refused; sub-agents of one session ask for approvals one at a time.
- **One YAML reading for what you consent to and what is applied.** The trust summary parses a project's `.k3code/config.yaml` with the pure-Python loader and the file was applied with libyaml's, which accepts documents the other rejects (a tab after a colon) and reads some differently; the applied text now uses the same loader. Your own config keeps the fast one.
- **MCP.** The restart throttle for a server that never connected counts from the moment its connection failed (it was stamped after the teardown), the early-start task is held and cancelled on shutdown, and the old connection of a restarted server is torn down beside the new one. **NetWatch** keeps its provider state across turns (it was replaced every turn, so the failure threshold was never reached across turns and each turn started a probe cycle): `PROVIDER_DOWN` can now be reached, `/model chain` can show `provider_down`, and parked retries wake on recovery. A running **Stop hook** gets ten seconds to finish when the gateway shuts down right after an answer.
- **Per-child cache numbers.** `subagent.complete` and the usage row carry each sub-agent's cache-read and cache-write tokens, its number of calls and its first call's numbers, so whether a cache-sharing fork would help can be measured; `/usage` cache hit rates now count them. `delegation.status` reports the current session's live children and the gateway's total; the agents view's pressure chip uses the session's parallel limit. The setup wizard writes `autonomy.agents.max_parallel` when a use asks for a fan-out wider than 4 (research asked for 6 and got 4).
- **The goal's advisor veto follows `autonomy.advisor_modes`.** It ignored the modes (auto by default, as for the plan critique): every goal, in every permission mode, paid a strong-tier call at each "done". Set `advisor_modes` to the modes you want it in.
- **A fan-out that starts on a loaded machine runs one child fewer at a time.** When CPU `some avg10` is above 50 or IO pressure is at its admission threshold (read once, from `/proc/pressure`, nothing where there is none), the width drops by one, never below one; `fanout.plan` says so (`pressure_shrink`). `$K3CODE_PSI_PATH` moves the PSI directory.
- **`parallel_safe` for MCP servers.** `mcp.servers.<name>.parallel_safe: true` lets calls to a read-only server in one reply run at the same time (three 0.4 s calls took 1.22 s in a row, about 0.4 s together). Off by default; a project's `.mcp.json` cannot set it; a call that needs approval still runs alone.
- **Numeric strings keep working for the agent limits.** `ultracode.max_agents: "12"` (a hand-written file, an environment variable) was read by `int()` before the keys were checked at load, and was refused by the check; digit strings are accepted again for the limits and for `ultracode.max_tokens`.
- **A goal at the `max_turns` cap pauses.** With goals that keep going, a goal whose turn stopped at the configured `max_turns` cap was retried for ever; the cap is a limit you set, so the goal pauses (`/goal resume` continues).
- **Turns start sooner and block less on the event loop.** MCP servers start while your hooks and the scope classifier run, and the MCP SDK is imported off the event loop (a slow stdio server added about two seconds before the first token, and its import blocked the loop for 0.6 s); a server that is down or hangs is no longer waited for on every turn (it was relaunched and waited for up to 35 s each time: a server that never connected is now throttled from its failure, a restart waits at most three seconds, and the old connection is torn down beside the new one); a failed connect releases whoever waits for it at once. `config.yaml` is parsed once per change instead of on every hook event, tool call and skills lookup (5 to 70 ms each, with libyaml's loader when present); a file edited in the last two seconds is always read afresh. NetWatch builds its TLS context once (a fresh one cost about 100 ms of event-loop time per probe) and probes the internet and every provider at the same time. The curator's duplicate scan tokenises each skill once (60 skills froze the loop for 300 ms). The final test run of an `/ultracode` pipeline is skipped when the last merge already ran the same command on the same tree and no fix changed it since (a test suite can take minutes; the report says so). The Stop hook runs after `message.complete`, so a slow hook no longer keeps the input locked (it still finishes before the next prompt and before a goal is judged). The plan advisor's critique runs beside the task instead of before it and is shown when it arrives.

## [0.1.0] - 2026-10-08 (alpha, not tagged)

The first version meant for people other than its author. It is alpha: the core works and is tested, but live-model behaviour, long unattended runs and multi-day use are not yet verified. The [Status section of the README](README.md#status) has the details.

### What works today

- **Coding agent.** Read, edit, patch, bash, grep, glob, web fetch and search, and todo tools. Plan mode, MCP servers, skills, project and user memory, output styles, and extra working directories.
- **Terminal UI.** An agent list under the input box with live states (working, needs input, completed, failed), focus mode, input history kept per project, slash commands with completion, and permission modes cycled with Shift+Tab.
- **Permissions.** Five modes (`default`, `accept-edits`, `plan`, `auto`, `yolo`), a hardline list that is refused in every mode, and approval rules saved per project. Bash runs in a bubblewrap sandbox in `auto`, `yolo` and background sessions when `bwrap` is available.
- **Provider routing.** An ordered chain of providers and models with error classification, cooldowns and failover. A long rate limit fails over instead of sleeping. Background work goes to cheaper tiers.
- **Reliability.** A connectivity monitor that pauses a turn while offline and resumes it by itself, retry with jittered backoff, a crash-safe journal of tool calls, a resource governor, and optional token and spend caps.
- **Autonomy.** Task scope classification, a planning turn for larger tasks, fan-out of independent parts into git worktrees with review and tests, `/goal`, `/loop`, `/ultracode` and `/ultraresearch`.
- **Automation.** Cron schedules and file, git, webhook, session, network and idle triggers, run by the daemon.
- **Learning.** A decision log, permission-rule suggestions, proposals, project preparation, and proposed changes to its own configuration, which can be A/B tested.
- **Setup and operations.** An installer for Linux and macOS, `install.ps1` for Windows (installs into WSL and adds `k3code` and `k3` commands to Windows), guided and resumable setup, `k3code doctor`, export and import bundles with secrets redacted, and an update command with rollback.
- **`k3`.** A multi-window terminal (a TUIOS fork) that shows agent states and pending approvals in its inbox.

### Not yet

- Live-model behaviour. Most exit checks use a scripted fake provider. The live-model rows ran through the `claude-cli` provider (a local Claude Code login).
- The 72-hour daemon soak. A 30-minute soak passed.
- Automatic resumption of interrupted turns in the daemon. `k3code doctor` flags unresolved journal entries.
- Platforms other than Linux on x86_64. macOS and Windows (through WSL) are untested on real machines. The installer is untested on Debian and on aarch64.
- The browser tool needs Playwright, which `presetup` installs. That path is untested on a clean machine.
- The update path against published releases. There are none yet, so the update and rollback path was only tested against local version directories.

### Changed before publication

- Hard-coded defaults that pointed at the author's own servers were replaced with neutral values. Web search has no default SearXNG instance, so the keyless DuckDuckGo fallback is used until `research.searxng_url` is set, and whenever that SearXNG is unreachable. The OmniRoute preset is no longer a default: the wizard offers Claude Code's own login when `claude` is installed, otherwise a custom endpoint. Existing configs that name it keep working. The hardline list names placeholder hosts.
- If you relied on the old defaults, set your own values in your config. To keep protecting your own hosts from remote service restarts, add patterns under `permissions.hardline`.
- Pull requests and pushes are checked for secrets (`.github/workflows/gitleaks.yml`).

### Fixed during the long-run audit

- Redaction, install and update, and TUI and mid-turn prompt findings.
- Gateway transport and sub-agent findings, and hardening of bash, file tools, permissions and the sandbox.
- Orphan tool results that were sent to providers on the second turn of a tool-using session.
- Two daemon bugs found by an earlier soak run, and single-instance daemon handling.
- A stall in the mem0 preference writer, which blocked every session while it ran.
